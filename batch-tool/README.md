# DMF Tester

该工具与主网页分离，但所有实验都通过正式 Node 后端的
`/api/session-state` 和 `/api/steps-from-message` 执行。
批量平台自身的页面、运行器、判定器、Skill、测试和启动入口均位于 `batch-tool` 子目录；
它不会复制或替换正式后端的液滴操作实现。

## 启动

```bash
npm run batch
```

打开 `http://localhost:3003`。如果 `3001` 端口上已有正式后端，工具会直接复用；
否则启动脚本会自动启动正式后端。
批量平台默认只监听 `127.0.0.1`，不向局域网开放。

## 输入表格

从工具页面下载模板。工作簿只有一张 `实验` 表，每行就是一条 Prompt。
普通实验只填一行；多流程实验使用相同实验编号，并按步骤 `1、2、3` 连续填写。
预期参数使用 `数量=3；位置=20,24；方向=右；尺寸=1x1` 这样的文本，不需要填写 JSON。
预期调用和参数只用于自动判定，绝不会发送给被测模型，也不会改变正式后端的执行。
手动实验可以留空，实验仍会正常运行，但结果会标记为待复核而不是自动通过。

缺省实验只有一个预设 Prompt。模型追问且没有工具调用、没有新增步骤时，工具才会发送
统一回答。多流程实验按步骤顺序在同一个会话中运行，不使用自动审计结果作最终判定，
完成后统一进入待人工复核；运行错误仍会单独标记。

结果审查页会按同一多流程实验的完整激活序列分组。序列完全相同的重复运行只显示一条
代表记录，并标明包含的重复序号。对代表记录作出的通过、失败或撤销判定会同步应用到该组
全部运行；不同序列保持为独立的待复核记录。

多流程的下一条 Prompt 发送前，批量工具会从上一轮实际操作中识别其输出液滴，并追加一段
自然语言界面观察，列出液滴数量、位置和尺寸。该观察只存在于测试工具发出的用户消息中，
不会修改正式后端的数据协议，也不会把挤出操作的源液滴误作新生成液滴。

自动判定不把 Prompt 中的坐标当成最终落点。它先核对正式后端记录的操作及参数，再用
项目自身的 `Squeeze`、`Move`、`RotateMix` 和 `Merge` 逻辑重放激活序列，并与后端返回
的原始序列逐步比较，同时检查网格边界。无法完成项目语义复核的运行会标记为待复核，
不会计为通过。

## 页面流程

工具按“方案设计、实验运行、结果审查、设置”组织。方案设计支持三种创建方式：

- 从 Excel 文件创建
- 在可视化编辑区手动创建
- 通过 AI 对话生成结构化草稿，再由用户复核

可视化编辑区使用紧凑表格式布局，自动生成实验编号、步骤序号和实验类型，并保留可编辑的实验分组。方案按
`YYYYMMDD-描述` 命名，每个方案是 `.local/projects` 下的独立目录，包含：

- `project.json`：方案元数据与当前版本
- `plan`：实验表格和结构化方案
- `ai`：该方案的 AI 设计对话
- `runs`：运行参数、日志、结果表、逐次 JSON、TXT 和 GIF

同名方案自动追加 `-02`、`-03` 等后缀。方案可重命名、删除、完整导入导出，也可单独清除
`runs` 回到实验设计阶段，同时保留实验方案与 AI 对话。以上本机数据不会提交到 Git。AI 生成器使用
`batch-tool/skills/generate-dmf-experiments` 中的实验设计 Skill，并与正式网页后端共用
当前 LLM 配置。

设置页可以更改本机的项目目录与兼容结果目录、保存和测试 LLM 配置、切换中文、英文、西班牙语与明暗主题，
也可以导入或导出配置。导出的配置不包含 API Key；项目内目录使用相对路径，便于在
Windows 和 macOS 间协作。

## 输出

关联方案的输出位于该方案的 `runs` 目录；未关联方案的兼容输出位于 `.local/experiments`。
每次任务生成独立目录，包含：

- `实验结果.xlsx`
- `运行状态.json`
- `实验` 目录中的逐次 JSON、TXT 和 GIF

实验记录会保存正式后端版本、Git commit、代码指纹、非敏感 LLM 配置、原始请求响应、
Token 使用量和自动判定依据。API Key 不会写入实验产物。
